# Employee API

## Назначение

Employee API — рекомендуемый программный интерфейс для получения данных сотрудника, работника, руководителя, подразделения и должности.

## Какие данные предоставляет

API предоставляет сущность [«Сотрудник»](../data/employee.md): `employee_id`, ФИО, подразделение, `manager_id`, должность и кадровый статус.

## Откуда получает данные

Source system — [1С ЗУП](../systems/1c-zup.md). API не использует Bitrix24 как источник кадровых данных.

## Протокол и аутентификация

- Protocol: REST over HTTPS.
- Authentication: service token, выданный конкретному приложению.
- Environments: `test`, `production`.

Реальные URL, токены и credentials намеренно не хранятся в каталоге.

## Как получить доступ

Следуйте [инструкции по доступу](../guides/how-to-get-access.md). Укажите сервис-потребитель, окружение, поля, цель использования и ожидаемую нагрузку.

## Пример использования

Концептуальный запрос: получить сотрудника по `employee_id`. Конкретный endpoint не опубликован в демонстрационном каталоге; после выдачи доступа он сообщается через утверждённый защищённый канал.

## Ограничения

API предназначен преимущественно для чтения. Зарплата, документы и другие избыточные персональные данные не возвращаются. Кэш может давать небольшую задержку после изменения в 1С ЗУП.

## Владелец и поддержка

Технический владелец — [отдел автоматизации](../teams/automation-team.md), бизнес-владелец данных — [HR-команда](../teams/hr-team.md).

## Частые вопросы

**Как получить руководителя сотрудника?** Прочитать `manager_id` через Employee API.

**Что делать, если поля нет?** Считать его незадокументированным и запросить дополнение каталога у владельца.
