# Как добавить информацию

{% note info %}

Три сценария: обновить доверенную сущность, создать новую по шаблону или передать сырой материал на разбор.

{% endnote %}

## Паспорт

| Сценарий | Результат |
| --- | --- |
| Изменить сущность | Исправленный Markdown и metadata проходят review. |
| Создать сущность | Новая карточка на основе шаблона, валидация и навигация. |
| Передать материал | Файл в `inbox`, который ещё не считается доверенным знанием. |

## Поток доверия

`RAW` → `inbox` → extraction → review → merge → trusted catalog

До review и merge материал не является фактом каталога и не должен попадать в ответы AI-экспорта.

## Частые вопросы

**Как исправить существующую страницу?** Измените Markdown и metadata, выполните валидацию и откройте merge request.

**Куда положить неразобранный документ?** В [`inbox`](../inbox/README.md); до review он не считается доверенным знанием.

{% cut "Изменить существующую сущность" %}

1. Найдите файл по навигации или стабильному ID.
2. Исправьте metadata и основной текст, сохраняя ссылки по ID.
3. Запустите `python scripts/validate_catalog.py`.
4. Сделайте commit и откройте merge request.

{% endcut %}

{% cut "Создать новую сущность" %}

1. Выберите файл в каталоге [`templates`](../templates/system.md).
2. Скопируйте его в соответствующий раздел и замените все подсказки.
3. Добавьте страницу в `toc.yaml` и индекс раздела.
4. Запустите `python scripts/validate_catalog.py` и `python scripts/build_ai_index.py`.
5. Сделайте commit и откройте merge request с владельцем в reviewers.

{% endcut %}

{% cut "Передать сырой материал и пройти review" %}

1. Положите старый Markdown, текст или заметку в [`inbox`](../inbox/README.md).
2. Создайте issue или merge request и укажите предполагаемого владельца.
3. Владелец каталога или будущий AI-процесс выделит сущности и связи.

Проверка перед merge: ID в kebab-case, связи только по ID, указан владелец и Source of Truth, нет секретов и реальных внутренних адресов, а валидация, AI-экспорт и сборка проходят успешно.

{% endcut %}
