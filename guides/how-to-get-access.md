# Как получить доступ

{% note info %}

Универсальный безопасный путь запроса прав к системе, данным или внутреннему API.

{% endnote %}

## Паспорт

| Факт | Ответ |
| --- | --- |
| Когда использовать | Нужны права к системе, данным или API. |
| Сначала найти | Нужный объект и его владельца в [каталоге](../index.md). |
| Кто согласует | Бизнес-владелец цели и состава данных. |
| Кто выдаёт | Технический владелец — только минимально необходимые права. |
| Секреты | Только через утверждённое хранилище, никогда не через Git или Markdown. |

## Шаги

1. Откройте страницу нужной [системы](../systems/index.md), [сущности данных](../data/index.md) или [сервиса](../services/index.md). Проверьте владельца, ограничения и рекомендуемый способ доступа.
2. Подготовьте запрос:

   - систему-потребитель и ответственную команду;
   - цель использования и необходимые поля;
   - тестовое или production-окружение;
   - ожидаемую частоту и объём запросов;
   - срок доступа.
3. Получите согласование бизнес-владельца. Для персональных данных требуется согласование [HR-команды](../teams/hr-team.md).
4. Получите минимально необходимые права у технического владельца и секрет через утверждённое хранилище.

## Частые вопросы

**К кому обращаться за доступом?** Сначала к бизнес-владельцу объекта, затем к его техническому владельцу; оба указаны в паспорте сущности.

**Какие данные указать в заявке?** Цель, потребителя, окружение, нужные поля, объём и срок доступа.

{% cut "Если способ доступа не описан" %}

Создайте запрос владельцу сущности. Не угадывайте endpoint, протокол или способ авторизации; до обновления каталога информация считается незадокументированной.

{% endcut %}
