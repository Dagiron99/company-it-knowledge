# Метрики эффективности каталога

В MVP сбор метрик не реализуется. Ниже зафиксирована методика для будущих фаз; перед запуском измерений необходимо выбрать период, владельца и источник данных.

## 1. Time to Information

Среднее и медианное время от получения вопроса до нахождения подтверждённого ответа. Измерять на повторяемом наборе задач до и после внедрения каталога.

## 2. Answer Success Rate

Доля запросов, для которых доверенная часть каталога содержит полный корректный ответ. Проверять экспертной разметкой benchmark-вопросов.

## 3. AI Retrieval Success Rate

Доля вопросов, где поиск AI вернул правильную сущность в top-k результатов. Эталонные ID должны быть заранее размечены человеком.

## 4. No-answer correctness

Доля запросов без документированного ответа, на которые AI корректно сообщил об отсутствии информации и ничего не выдумал.

## 5. Catalog Coverage

Отношение числа документированных систем к числу известных систем в согласованном реестре. Источник реестра и правила исключения должны быть зафиксированы.

## 6. Ownership Coverage

Доля сущностей с существующим `owner`, прошедшим ссылочную валидацию. В MVP валидатор уже требует 100%, но метрика должна учитывать актуальность владельца.

## 7. Integration Coverage

Доля критичных интеграций, представленных отдельной сущностью с источником, получателем, данными, расписанием и владельцем.

## 8. Documentation Freshness

Доля сущностей, обновлённых или подтверждённых владельцем за последние N месяцев. Значение N выбирается по criticality, а не единообразно для всего каталога.

## 9. Expert Interrupt Reduction

Изменение числа обращений экспертам вида «где взять?», «кто отвечает?» и «как подключиться?». Сравнивать одинаковые периоды и нормировать на количество сотрудников.

## 10. Onboarding Time

Время, необходимое новому IT-сотруднику для прохождения заданного набора сценариев и корректного объяснения ключевых систем и связей.

## Правила измерения

- Использовать один версионируемый benchmark, начиная с [`tests/questions.md`](tests/questions.md).
- Отделять отсутствие знания от ошибки поиска.
- Сохранять ссылку на конкретный commit каталога для каждого измерения.
- Не считать ответ успешным без подтверждаемого источника.
