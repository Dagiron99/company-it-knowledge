# Синхронизация сотрудников 1С ЗУП → Bitrix24

{% note info %}

Интеграция передаёт разрешённую часть кадровых данных из 1С ЗУП в Bitrix24, чтобы в портале отображались актуальные профили сотрудников.

{% endnote %}

## Паспорт

| Факт | Ответ |
| --- | --- |
| Поток | [1С ЗУП](../systems/1c-zup.md) → [Bitrix24](../systems/bitrix24.md) |
| Данные | Разрешённая часть [сотрудника](../data/employee.md) |
| Частота | Каждые 15 минут (`every-15-minutes`) |
| Метод | REST |
| Технический владелец | [Отдел автоматизации](../teams/automation-team.md) |
| Бизнес-владелец данных | [HR-команда](../teams/hr-team.md) |

## Связи и поток данных

[1С ЗУП](../systems/1c-zup.md) → **синхронизация сотрудников** → [Bitrix24](../systems/bitrix24.md).

Передаются стабильный ID, ФИО, должность, подразделение, руководитель и статус занятости. Зарплатные данные не передаются. Bitrix24 получает копию, а Source of Truth остаётся в 1С ЗУП.

## Частые вопросы

**Как часто данные передаются?** Каждые 15 минут; поэтому профиль в Bitrix24 может отставать от Source of Truth.

**Что сломается при остановке?** Портал продолжит работать, но профиль, отдел и руководитель могут устареть; данные в 1С ЗУП не пострадают.

{% cut "Действия при ошибке" %}

Проверьте время последнего успешного запуска и журнал с correlation ID, затем передайте их владельцу. Не исправляйте кадровые данные вручную в Bitrix24: следующая синхронизация перезапишет копию.

{% endcut %}

{% cut "Эксплуатация и мониторинг" %}

Интеграция зависит от доступности 1С ЗУП и Bitrix24. Ожидаемые метрики: время последнего успеха, число обработанных записей и число ошибок.

Конкретная система мониторинга в MVP не задокументирована, поэтому ссылку на dashboard нельзя придумывать.

{% endcut %}
